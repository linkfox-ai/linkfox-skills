# 确认策略

## 可直接执行(不需要额外一轮确认)

- 解释 flow 或某个节点在做什么(`explain`)。
- 结构校验(`validate`)。
- 在不输出完整 JSON 的前提下给出候选方案、节点建议或差异预览。
- 在同一轮里追加澄清问题(`needs_input`)。
- **明确的 `generate` 请求**:用户描述已经足以确定节点组成和主干结构(例如"最简工作流"、"BusinessStart → DirectReply"、"只用 X 和 Y 节点"、"不调用 AI/API"、给了明确输入输出),不必再问,不必再等一轮"确认"。当轮内先用 1-2 句自然语言宣布方案,紧接着直接落盘并上传。
- **用户显式催促**:出现"立即/马上生成"、"不要再问"、"直接生成"、"就这样做"等催促词,无论上一轮是不是在等确认,都视为对当前最合理方案的授权,当轮直接落盘并上传;不要再问澄清问题,也不要再要一次"确认"。
- **`refine` 的小改动**:仅改单个节点的 prompt 文本、显示名、说明,或添加一条 sticky note,不改结构、不删节点/边,可当轮直接跑落盘和上传,只需在自然语言里简述改了什么。
- **节点级 `refine`**(标签带 `nodeId`,用户在画布上点了某个节点):用户已经指明了改哪个节点,**改这一个节点的 `inputs` / `label` / `description` 不用再确认一轮**,当轮直接落盘上传,回复里点出"只改了这一个节点"。**但联动面一旦超出该节点自身就回到普通 refine 的确认门槛**:换节点类型、增删节点或 edge、因输出字段改名要连带改多个下游引用 —— 这些是结构性改动,先说清影响范围再等确认。
- **查看执行记录(`runs`)**:纯读动作,不触发执行、不改 flow、不删记录,当轮直接查、直接汇总。

## 必须先请求确认

只有在下列情况才需要单独一轮确认再执行:

- `generate` 时关键需求含糊不清(触发方式、是否需要 AI/知识库/外部 API 都没说,或用户抛的是宽泛目标而不是流程结构)。
- `refine` 涉及结构性改动:删除节点或 edge、改分支(Condition / ConditionAgent / HumanInput)、改循环/迭代拓扑,或一次性改多个节点的 `inputs`。
- 用户明确说"先给我看看方案"、"别急着生成"、"我要先确认"。
- **`run`(执行一次)始终需要用户明确要求**。这不是"要不要多问一轮"的问题:执行会产生真实副作用(SendNotification 真发通知、WriteFile 真写表、HTTP/LinkfoxHTTP 真打接口、CrossBorderExpert 可能计费),所以只有用户自己说了"跑一下 / 执行一次 / 手动触发一次"才能跑。用户已经明确要求执行时,不要再多问一轮"确认吗",直接跑 —— 但含上述副作用节点时,先用一句话点出会发生什么实际动作。

需要确认时:用一段自然语言列出动作、涉及节点、影响范围;不贴完整 JSON,不贴内部字段路径或颜色码;末尾一句请求确认。

对唯一待确认 generate/refine 计划的确认同时授权以下有限动作:生成完整 JSON、落盘、通过 `scripts/upload_workflow.py` 创建或更新当前 workflow。**确认生成/修改不授权执行** —— 想跑一次必须用户另外明确说"跑一下 / 执行一次"。确认也不授权发布、删除 flow,不授权删改执行记录或查询其他 linkfox-workflow 系统资源。

确认 refine 只授权覆盖当前 workflow 的原文件和原 workflowId,不授权另存副本。创建第二份 workflow 必须有用户明确的“新建另一份/不要覆盖原流程”等指令;“继续”“修改”“优化”“改名”都不是新建授权。

确认前用业务语言展示:动作、涉及节点、影响范围;不要展示完整 JSON,不要展示内部字段路径或颜色码。

## 短回复

- 上一轮有唯一待确认计划(generate/refine)时,"继续"/"可以"/"确认"/"OK"/"好"视为确认,直接生成、落盘并上传 JSON。
- **短确认永远不能触发 `run`**:上一轮在等生成/修改确认时,"可以 / 继续"只授权落盘上传;只有上一轮问的就是"要不要执行一次",短确认才是执行授权。分不清就再问一句。
- 上一轮同时有多个待选方案或多处改动待确认时,短回复不能触发输出,必须再次说明要确认哪个。
- 无待确认动作时,短回复不能猜为 generate/refine/export。
- 当前已有 workflow时,短回复确认 refine计划必须复用原 path;不得重新选择 slug。

## 异常与阻塞

- 用户提供的原 JSON 不是合法 agentflow v2:立刻反馈,不修不猜。
- 用户需求超出 24 个节点表达能力:明确说不支持,给最近替代。
- LinkFox身份解析、导入或 mapping 校验失败:保留已落盘 JSON,报告具体阶段;禁止输出 `<linkfox-flow-info>`。若 linkfox-workflow 系统已返回 workflowId 但 mapping 未确认,也不得把部分成功包装成完整成功或自动重试上传。
- 用户要求发布、删除 flow,删改执行记录,或查询 model / credential / documentStore 目录:明确说明不支持。用户明确要求上传一份已提供且已校验的最终 JSON时,该请求本身可视为上传确认,直接走上传脚本;同理,用户明确说"跑一下这个流程"本身就是执行授权,直接走 `run_workflow.py`,不必再要一次确认。
- 用户要求执行或查执行记录但没有 workflowId:问一次是哪个流程,不猜、不拿展示名反推。
- 用户在生成过程中中途改需求:把上一版计划作废,重新走 generate/refine 流程,不要在旧 JSON 上强行打补丁。
- validate 发现 error 级问题:输出前必须修复;修复过程要在自然语言里点出改了什么。
