# Kalodata TikTok 视频榜单与详情

## 适用范围

### 适用

发现 TikTok Shop 高表现带货视频，或查看已知视频的带货和互动数据。用户无需明确提及 Kalodata。

**场景速查**

| 用户表达 | 查询场景 |
|---|---|
| TikTok 视频榜单、视频排行、热门视频、爆量视频 | 按市场和时间查看带货视频榜单。 |
| TikTok 带货视频排行、top TikTok videos | 发现特定市场的高表现带货视频。 |
| 按 GMV 筛选或排序视频 | 查看符合销售额条件的榜单。 |
| TikTok 视频详情、带货视频数据 | 查看指定视频的完整表现。 |
| 视频播放量、互动数据、视频 GPM | 分析视频互动与变现表现。 |
| kalodata video search/detail | 按榜单发现或单个视频深查处理。 |

### 边界

商品、达人、店铺和直播的榜单或详情使用对应 Kalodata 技能。关键词搜索、广告活动管理、视频编辑、视频下载和内容创作不属于本技能范围。

## 接口清单

| 接口 | 端点 | 对应脚本 | 说明 |
|---|---|---|---|
| 视频榜单 | POST `/kalodata/video/rank` | `scripts/kalodata_video_search.py` | 发现热门带货视频并获取后续深查所需编号。 |
| 视频详情 | POST `/kalodata/video/detail` | `scripts/kalodata_video_detail.py` | 获取单个视频的互动、销售、广告与达人数据。 |

## 前置条件

确认目标市场和统计区间；查询详情前先取得视频编号，可来自用户提供的编号、TikTok 视频链接或榜单结果。参数及使用限制见 `references/api.md`。

## 查询流程

1. 用户需要排行、热门视频或发现候选时，先查看视频榜单；已有视频编号或已选定榜单视频时，直接查询详情。
2. 需要从发现进入深查时，选择榜单中的 `video_id`，作为详情查询的 `videoId`，保持市场、统计区间和币种一致。
3. 先展示当前结果，再根据用户任务选择是否深查或继续翻页；失败、空结果及继续调用遵守成本约束和接口参考中的处理要求。

## 执行方式

- **直接调用接口**：接口端点、完整参数、响应和错误码见 `references/api.md`。
- **脚本调用（推荐）**：`python <脚本路径> '<JSON 参数>' [--inline] [--no-cache]`。
- **成本约束**：本工具会消耗算力。同一会话、同一参数组合默认只调用一次，脚本提供 24 小时本地缓存。失败或空结果时，不得自动更换关键词、翻页或修改邮编连续试探；需要继续检索时，先向用户说明额外消耗。

### 输出策略

- 完整响应以 JSON 保存，目标路径为 `<cwd>/linkfox/<YYYY-MM-DD>/<session>/data/linkfox-kalodata-tiktok-video-<接口标识>-<timestamp>.json`。`<cwd>` 为脚本运行时的工作目录，`<session>` 优先取环境变量 `SESSION_ID`，用于聚合同一任务的数据。禁止写入 `/tmp`，当前目录不可写时应报错。
- HTTP、业务或响应格式错误时，脚本报告原因并以非零状态退出。HTTP 成功但响应不是 JSON 对象时，没有结果文件。
- 响应体不超过 8 KB：保存后，将完整 JSON 打印到标准输出。
- 响应体超过 8 KB：保存后，标准输出仅展示摘要，包括顶层字段、常见计数（如 `total`、`costToken`，仅在响应中存在时展示）、最大列表字段的长度和前 3 条样本。
- 添加 `--inline` 可强制全量打印到标准输出，同时仍保存文件。

先通过摘要判断数据是否足够。需要具体字段时，优先使用 `jq` 或 `ConvertFrom-Json` 从保存的 JSON 文件按需提取，避免将整份响应载入上下文。

## 执行规则

### 算力消耗预估

7.0 算力 / 次；榜单和详情分别计次。

**声明**：算力消耗以实际扣除为准；如因需要调整算力消耗标准，恕不另行通知。最终解释权归 LinkFox 官方所有。

用户会因算力消耗而支付费用。需要高频调用或用户对消耗量预期不足时，提醒用户，并由用户决定是否继续。

### 解决认证和算力问题

出现以下情况时，按 `references/onboarding.md` 的指引处理：

- 未配置接口密钥：`LINKFOX_AGENT_API_KEY` 和 `LINKFOXAGENT_API_KEY` 均为空。
- HTTP 状态码为 `401` 或 `402`。
- 响应提示算力或余额不足、计费不足、配额超限、套餐到期或需要充值。英文错误消息也按其含义判断。

### 约束与建议

- **清晰展示榜单**：用表格展示标题、视频编号、播放量、互动、GMV、广告指标及达人用户名；保留返回顺序，除非用户明确要求接口支持的排序。
- **分组展示详情**：按视频身份、互动、变现、广告、达人、时长和关联商品数组织单个视频资料。
- **标明统计口径**：展示指标时始终注明 `dateRange`、`region` 和 `currency`。数据可能有 T+1 统计延迟，不当作实时值。
- **正确解释指标**：`revenue` 为 GMV，不是利润或广告支出；`video_gpm` 为每千次播放 GMV，不能展示为百分比。保留 `sales_volumn` 的原始拼写。
- **保留编号精度**：视频编号按字符串处理；不要转换为可能丢失大整数精度的数字。
- **说明返回范围**：展示本次取得的视频，不补造总量和缺失指标。返回数量、分页边界、无关键词检索及错误处理见 `references/api.md`。

## 使用示例

### 查看美国市场热门带货视频

用户：看看美国市场最近一周有哪些热门带货视频。

确认市场、区间和币种后查看榜单，展示播放、互动、GMV、广告指标和所属达人。

### 按 GMV 筛选并排序

用户：看看 GMV 在 1 到 100 美元的视频，按 GMV 从高到低排列。

确认统计范围，按接口参考准备 GMV 筛选与排序，展示返回顺序及统计口径。

### 从榜单深入分析单个视频

用户：把榜单中这个视频的 GPM、销量和广告表现展开看看。

将选定视频的 `video_id` 用于详情查询，保持查询口径一致，分组展示详情并解释指标含义。
