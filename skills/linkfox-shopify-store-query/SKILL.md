# Shopify 店铺查询

## 适用范围

### 适用

查找或筛选 Shopify 独立站店铺，并对比店铺的流量、订单、商品、广告及社媒表现。

**场景速查**

| 用户表达 | 查询场景 |
|----------|----------|
| 找美国的 Shopify 服装独立站 | 按名称或域名关键词与国家发现店铺。 |
| 找近年创建、有一定商品和广告规模的店铺 | 组合店铺年限、产品数和广告数筛选。 |
| 看这些独立站的月访问量和订单表现 | 按月访问量、月订单量筛选并排序。 |
| 找 Facebook 或 Instagram 粉丝较多的店铺 | 按社媒粉丝排序，对比返回的粉丝指标。 |
| 查竞品的广告库和联系信息 | 展示返回的广告库、社媒主页及邮箱。 |

## 前置条件

明确店铺查询目标及筛选范围；参数定义与取值规则见 `references/api.md`。

## 查询流程

1. 明确要发现或对比的店铺范围，按用户目标准备筛选与排序；完整入参和限制见 `references/api.md`。
2. 调用前按接口文档估算动态消耗。必须提醒用户本技能可能一次性消耗大量算力，由用户决定是否继续；同参数优先复用已有响应或缓存。
3. 在用户决定继续后执行查询，先检查摘要和响应状态；失败或空结果按接口文档解释，保留已取得的数据。
4. 展示本次匹配店铺及返回范围。需要继续翻页时，先说明下一页是新请求、会另行计费，再按用户决定继续。

## 执行方式

- **直接调用接口**：接口端点、完整参数、响应和错误码见 `references/api.md`。
- **脚本调用（推荐）**：`python scripts/shopify_store_query.py '<JSON 参数>' [--inline]`。
- **成本约束**：每次查询按本页返回店铺数 × 1.8 算力计费。同一会话、同一参数组合默认只调用一次，脚本提供 24 小时本地缓存。失败或空结果时，不得自动更换关键词、翻页或修改筛选条件连续试探；需要继续检索时，先向用户说明额外消耗。

### 输出策略

- 始终保存完整响应，目标路径为 `<cwd>/linkfox/<YYYY-MM-DD>/<session>/data/linkfox-shopify-store-query-<timestamp>.json`。`<cwd>` 为脚本运行时的工作目录，`<session>` 优先取环境变量 `SESSION_ID`，用于聚合同一任务的数据。禁止写入 `/tmp`，当前目录不可写时应报错。
- 响应体不超过 8 KB：保存后，将完整 JSON 打印到标准输出。
- 响应体超过 8 KB：保存后，标准输出仅展示摘要，包括顶层字段、常见计数（如 `total`、`costToken`）、最大列表字段的长度和前 3 条样本。
- 添加 `--inline` 可强制全量打印到标准输出，同时仍保存文件。

先通过摘要判断数据是否足够。需要具体字段时，优先使用 `jq` 或 `ConvertFrom-Json` 从保存的 JSON 文件按需提取，避免将整份响应载入上下文。

## 执行规则

### 算力消耗预估

消耗算力 = 本页返回店铺数 × 1.8。翻到下一页是新请求，按该页返回条数另行计费，不按匹配店铺总数一次计费；示例见 `references/api.md` 的「使用限制与计费」。本技能可能一次性消耗大量算力，必须提醒用户，由用户决定是否继续。

**声明**：算力消耗以实际扣除为准；如因需要调整算力消耗标准，恕不另行通知。最终解释权归 LinkFox 官方所有。

用户会因算力消耗而支付费用。需要高频调用或用户对消耗量预期不足时，提醒用户，并由用户决定是否继续。

### 解决认证和算力问题

出现以下情况时，按 `references/onboarding.md` 的指引处理：

- 未配置接口密钥：`LINKFOX_AGENT_API_KEY` 和 `LINKFOXAGENT_API_KEY` 均为空。
- 响应状态码为 `401` 或 `402`。
- 响应提示算力或余额不足、计费不足、配额超限、套餐到期或需要充值。英文错误消息也按其含义判断。

### 约束与建议

- **区分本页和总量**：`total` 是本页返回条数，`storeNum` 才是符合条件的店铺总数，不能将本页条数当作市场店铺总量。
- **清晰展示数据**：以表格展示店铺名称、域名、国家及与用户目标有关的产品、类目、月访问、月订单、社媒粉丝和广告指标；缺失字段不补造。
- **保留指标表达**：月访问量与月订单量可能为格式化值，按响应展示，不擅自转换为精确数字。
- **按需展示链接**：仅展示响应中实际提供的店铺、广告库、社媒链接及联系信息，不推断未返回的资料。
- **区分排序与筛选**：粉丝数用于可用的排序和展示，是否存在对应筛选条件以接口定义为准。
- **解释错误和空结果**：遵守接口文档的基础响应规则；上游无数据也可能报错，不把所有错误都解释为无匹配店铺。

## 使用示例

### 发现美国 Shopify 服装店铺

用户：帮我找美国的 Shopify 服装独立站。

明确关键词与筛选目标，说明预估消耗并由用户决定继续后，查询并展示店铺及本次返回范围。

### 对比高流量或高粉丝店铺

用户：我想比较这些独立站的访问量和社媒表现。

按用户选择的指标排序，展示实际返回的月访问量、月订单量、Facebook 与 Instagram 粉丝等信息；进一步翻页前说明额外消耗。
