# 多参考图生视频

## 适用范围

### 适用

根据多张图片综合生成动态视频，并保存生成的视频供用户使用。

**场景速查**

| 用户表达 | 使用场景 |
|---|---|
| 把这几张产品图做成展示视频 | 多图参考生成商品视频。 |
| 多张图片生成视频，保留不同角度 | 按参考图和动态描述准备生成。 |
| 当前有哪些多图视频模型可以选 | 查询当前开放模型及其能力。 |
| 视频还在生成，查一下原任务 | 只查询已有任务，不重复提交。 |

### 边界

单图或首尾帧视频使用 `linkfox-aigc-videogen`；图片生成使用 `linkfox-aigc-imagegen`；文本生成使用 `linkfox-aigc-textgen`。

## 前置条件

先确定参考图片、预期动态效果及用户选择的模型和画面要求。模型能力及参数定义见 [references/api.md](references/api.md) 和 [references/model-config.md](references/model-config.md)。已有公开图片链接可直接使用；本地图片或附件按 [references/file-upload.md](references/file-upload.md) 准备，上传前须告知文件将获得公开 URL，确认内容可以公开，禁止上传敏感或私密内容。

## 生成与交付流程

1. 先通过[查询模型枚举](references/api.md#接口查询模型枚举)获取当前可用模型及能力，并遵循用户选择；仅查询失败时使用文档中的静态列表兜底。
2. 准备图片素材，按原顺序复用公开链接或替换为上传成功的链接。上传失败先停止并解释原因；生成脚本不自动上传，查询原任务时不重复上传。
3. 按用户选择准备请求，调用生成脚本创建一次任务。普通 JSON 生成直接使用传入参数和默认策略，不额外查询或存档模型配置，不添加模型白名单校验，不静默改写参数。
4. 获得任务编号后，沿用 [接口参考中的轮询策略](references/api.md#接口查询任务状态)。完成后自动下载视频到当前会话的 `media/`，并静默存档完整响应。
5. 将媒体交付标记后的本地路径提供给用户。错误或等待超时按 [脚本退出码与续查](references/api.md#脚本退出码与续查) 解释，保留原任务编号；只续查原任务，不自动重建任务或换模型，不在同一轮反复等待。

## 执行方式

- **直接调用接口**：接口端点、完整参数、响应和错误码见 `references/api.md`。
- **脚本调用（推荐）**：`python scripts/aigc_videogen_multi.py '<JSON 参数>' [--inline] [--no-cache]`。
- **成本约束**：生成任务按所选参数动态计费。同一会话、同一参数组合只创建一次任务；脚本不读取或保存响应缓存，`--no-cache` 为兼容标记。失败、空结果或等待超时只续查已有任务，不自动重建或换模型。用户要求另建任务时，先说明会产生额外消耗。

### 输出策略

- 生成成功时，视频下载到会话 `media/`，标准输出为 `Saved full response: <本地路径数组>`；将其中本地视频路径交付给用户。完整响应静默存入会话 `data/`，不向用户展示临时媒体 URL。
- 失败或等待超时时，标准输出包含诊断文件路径及错误摘要，`dataFile` 指向完整诊断；存档失败时为 `null`。JSON 诊断路径不是视频交付结果。
- 会话根目录依次尝试 `ACPX_WORKSPACES` 首路径、当前工作目录、用户目录和系统临时目录下的 `linkfox/`；会话路径为 `<root>/<YYYY-MM-DD>/<session>/`，`<session>` 优先取 `SESSION_ID`。响应和媒体共用同一会话。
- 模型目录输出配置 JSON，完整目录存档到 `data/`；超过 8000 字节时默认仅输出模型名称和请求值摘要，可用 `--inline` 输出完整能力。生成模式接受 `--inline`，但它不改变媒体交付协议。

需要诊断字段或模型能力时，使用 `jq` 或 `ConvertFrom-Json` 从保存的 JSON 按需提取；禁止读取转存的视频内容。

## 执行规则

### 算力消耗预估

生成任务按所选参数动态计费，无固定算力单价。实际用量可参考创建响应的 `costToken`，以实际扣除为准；该字段缺失时脚本记录的 `0` 不表示免费。

**声明**：算力消耗以实际扣除为准；如因需要调整算力消耗标准，恕不另行通知。最终解释权归 LinkFox 官方所有。

用户会因算力消耗而支付费用。需要高频调用或用户对消耗量预期不足时，提醒用户，并由用户决定是否继续。

### 解决认证和算力问题

出现以下情况时，按 `references/onboarding.md` 的指引处理：

- 未配置接口密钥：`LINKFOX_AGENT_API_KEY` 和 `LINKFOXAGENT_API_KEY` 均为空。
- HTTP 状态码为 `401` 或 `402`。
- 响应提示算力或余额不足、计费不足、配额超限、套餐到期或需要充值。英文错误消息也按其含义判断。

### 约束与建议

- **异步业务专用约定**：生成成功时将媒体交付标记后的本地路径交给用户；失败时查看错误摘要与诊断文件。模型目录输出配置数据，避免误当作媒体结果。缓存、会话目录和 CLI 约定见 [运行约定](references/api.md#cli-与缓存)。
- **模型展示**：介绍、推荐、确认和解释错误时，仅使用动态目录的 `name`；查询失败时使用 [静态模型能力表](references/api.md#静态模型能力) 的说明名称。禁止向用户展示 videoType、provider、模型 code、内部请求值或渠道名称；MiniMax H3 的多个渠道只展示为 MiniMax H3。
- **选择建议**：一般多图参考可优先考虑可灵Omni；需要默认 2K 画面时可考虑 MiniMax H3。仍以当前目录和任务需求为准，不将静态表或路由示例当作名称白名单。没有合法默认值时让用户选择，不自动改参数或换模型。
- **交付展示**：只展示转存后的本地视频路径；禁止读取视频文件内容、展示 base64 或向用户提供原始 API 的带签名临时 URL。生成时间通常较长，应说明处理中状态。
- **状态解释**：区分客户端停止等待、服务端失败和媒体下载失败；等待超时不能解释为后端失败或已回补。空体和非 JSON 仅说明上游响应异常，不编造模型不可用原因。
- **能力与执行分离**：动态能力用于介绍和选择，不改变既有请求值、业务范围、默认模型、缺参追问或普通生成链路。模型与网关地址独立配置，测试环境须同时配置两个地址，详见 [模型目录参考](references/model-config.md)。
- **避免重复消耗**：创建任务只尝试一次；查询和素材准备遇到错误时，按对应接口参考处理。
