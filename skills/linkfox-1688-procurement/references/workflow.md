# 1688 采购异常与能力边界

完整采购流程见 [SKILL.md 的采购流程](../SKILL.md#采购流程)，字段、返回及脚本选项见 [接口定义](api.md)。本页只补充不常见的运行边界。

## 浏览器完成授权后跳到 MyERP 登录页

该跳转不能证明授权失败。使用当前 LinkFox 身份查询授权账号，以检查结果为准；不要要求用户复制浏览器回调码或手工修复令牌。

## 商品数量和费用与预期不符

核对商品返回的售卖单位、起批量或最小采购量。按瓦、米等单位计价时，不把一个计价单位误解为一件商品。预览明确失败或商品行无效时停止创建订单；后续请求需遵循请求约束。

## 预览返回多个分组

按 [orderPreview 接口定义](api.md#接口下单预览orderpreview) 核对全部分组和全部请求商品。整体金额是各组对应金额之和，任一组某项金额缺失时整体该项为 null；真实零值不等于缺失。交易方式、支付渠道和优惠仅适用于所属组，多组预览不代表可以合单，也不能按分组顺序推断创建后子订单的商品归属。

## 创建订单返回多笔或部分失败

按 [createOrder 接口定义](api.md#接口创建订单createorder) 保留完整响应与全部成功子订单号，再报告失败原因。部分成功不代表没有生成订单；继续支付、物流或其他履约操作时明确选择具体订单，沿用原有逐次确认要求。

## 提示创建成功但订单号为空，或请求结果不确定

多订单返回时兼容单订单号可能为空，先检查完整子订单列表。若列表未返回、无法识别订单号，或旧版后端提示“创建订单成功但订单号为空，请稍后重试或联系支持”，应告知用户结果待核实，先在 1688 买家订单中核对本次请求，不把它当成已确认未下单。

已有可确认的订单号时可按用户请求查询原订单；没有订单号时请用户提供核对后的订单号，或联系后端支持检查原请求。不得依据错误中的“稍后重试”重新创建订单，也不能更换外部订单标识或重新预览后自动重放整批采购。记录保存失败时从原响应恢复已知订单号，不再次调用创建接口。

## MCP 停用后仍可通过技能调用

MCP 启用/停用只控制工具列表暴露。本技能业务脚本通过公共调用器访问 tool-gateway HTTP 路由；彻底禁用某项采购能力需关闭对应 gateway 路由或后端操作，仅从 MCP 列表移除不足以关闭 HTTP 能力。

## 能力范围

不暴露 /alibaba1688/proxy/callback、/alibaba1688/authorizeCallback 或 /alibaba1688/oauth/callback。令牌交换和保存由 MyERP/ecom-plat 后端完成；不查询数据库修复授权，不使用 _dataQuery_executeDynamicQuery 获取实时采购响应。
