# 视频编辑

## 适用范围

### 适用

用户已有源视频，希望根据指令和可选参考图片完成编辑，并取得生成结果时，使用本技能。

**场景速查**

| 用户表达 | 编辑场景 |
|---|---|
| 把这段视频的背景换成摄影棚，保留商品 | 背景替换与主体保持。 |
| 按参考图调整视频风格 | 结合参考图片修改已有视频。 |
| 保持人物动作，把衣服改成深蓝色 | 依据编辑指令修改局部外观。 |
| 上次任务还没完成，继续查一下 | 恢复已有任务并下载结果。 |

## 模型选择

先通过[查询模型枚举](references/api.md#接口查询模型枚举)获取当前可用模型及能力，并遵循用户选择；仅查询失败时使用文档中的静态列表兜底。

## 前置条件

准备源视频、编辑要求和用户提供的参考图片。执行前阅读 [references/api.md](references/api.md)、[素材上传定义](references/file-upload.md) 和 [运行约定](references/runtime.md)，核对模型能力、工作目录可写性和 Windows UTF-8 启动方式；输出必须留在当前目录时先取消本次调用的 `ACPX_WORKSPACES` 设置。

## 执行流程

1. 按接口定义准备编辑任务，向用户说明模型时使用友好名称。完整流程运行 `python <skill-root>/scripts/run_task.py '<JSON 参数>'`；长参数可从文件或标准输入读取，具体选项见 [运行约定](references/runtime.md)。
2. 流程先通过本目录内置上传入口处理每个不同的源素材；本地文件和外部 URL 均先上传，复用本次上传映射并保留多图顺序。上传失败立即停止，上传全部完成后才创建任务。
3. 只创建一次并保存已接受的任务编号，随后查询至终态。超时后运行 `python <skill-root>/scripts/run_task.py --task-id <已保存编号>` 恢复，不再上传或重建任务；失败、未知状态或认证及计费错误时停止，并保留已有结果。
4. 成功后将结果下载到会话媒体目录，同时保留查询 JSON 和资产清单。下载失败只运行 `python <skill-root>/scripts/download_results.py <已保存查询JSON>` 重试下载。
5. 从 `Saved full response: ["<绝对媒体路径>", ...]` 读取生成文件；结合资产清单交付媒体、下载失败项及实际查询费用。显式使用低层创建或查询入口时，仍须完成上传和成功结果下载步骤。

## 执行方式

- **直接调用接口**：接口端点、完整参数、响应和错误码见 `references/api.md`。
- **脚本调用（推荐）**：`python <脚本路径> '<JSON 参数>' [--inline] [--no-cache]`。
- **成本约束**：视频编辑按模型单价与计费时长消耗算力，具体规则见“算力消耗预估”。同一会话、同一参数组合默认只调用一次，脚本提供 24 小时本地缓存。生成失败或超时不得自动更换模型、重建任务或增加数量；下载失败只重试下载，继续生成前说明额外消耗。

### 输出策略

- 始终保存完整响应，目标路径为 `<cwd>/linkfox/<YYYY-MM-DD>/<session>/data/linkfox-aigc-video-edit-<接口标识>-<timestamp>.json`。`<cwd>` 为脚本运行时的工作目录，`<session>` 优先取环境变量 `SESSION_ID`，用于聚合同一任务的数据。禁止写入 `/tmp`，当前目录不可写时应报错。
- 响应体不超过 8 KB：保存后，将完整 JSON 打印到标准输出。
- 响应体超过 8 KB：保存后，标准输出仅展示摘要，包括顶层字段、常见计数（如 `total`、`costToken`）、最大列表字段的长度和前 3 条样本。`costCredit` 可从保存的 JSON 按需提取。
- 添加 `--inline` 可强制全量打印到标准输出，同时仍保存文件。

先通过摘要判断数据是否足够。需要具体字段时，优先使用 `jq` 或 `ConvertFrom-Json` 从保存的 JSON 文件按需提取，避免将整份响应载入上下文。

## 执行规则

### 算力消耗预估

视频编辑扣点数 = 模型单价（点/秒）× 计费时长（秒）。固定时长模型按 `videoTime` 计费；跟随源视频的模型按源视频实际时长向下取整计费。六个模型的单价见 [视频编辑接口定义](references/api.md)，参考图不额外增加扣点。素材上传免费 （限时）。创建响应的零费用仅表示受理阶段，不代表免费；最终以查询响应及费用响应头为准，缺失时说明未知。

**声明**：算力消耗以实际扣除为准；如因需要调整算力消耗标准，恕不另行通知。最终解释权归 LinkFox 官方所有。

用户会因算力消耗而支付费用。需要高频调用或用户对消耗量预期不足时，提醒用户，并由用户决定是否继续。

### 解决认证和算力问题

出现以下情况时，按 `references/onboarding.md` 的指引处理：

- 未配置接口密钥：`LINKFOX_AGENT_API_KEY` 和 `LINKFOXAGENT_API_KEY` 均为空。
- HTTP 状态码为 `401` 或 `402`。
- 响应提示算力或余额不足、计费不足、配额超限、套餐到期或需要充值。英文错误消息也按其含义判断。

### 约束与建议

- requestId 为可选兼容字段；提供时原样转发，缺失时不自动生成。超时使用已接受的 taskId 恢复查询，不自动重新创建。

- **区分受理与完成**：获得任务编号表示任务已接受，只有成功终态及实际生成文件才能作为交付；JSON 文件不是生成视频。
- **保留同一任务身份**：提供 requestId 时，新任务使用新的唯一值，同一操作的核查保留该值；恢复查询使用已接受的 taskId。超时或失败不得自动换模型、重建任务或增加数量；继续生成前说明额外消耗。
- **展示本地媒体**：图片用 Markdown `![说明](<绝对路径>)` 展示，视频使用本地链接或播放器。说明任务状态、下载失败和实际费用，不读取二进制媒体，不向用户重复原始协议输出行。
- **保护敏感信息**：不展示密钥、授权头、Base64、内部工具标识或带签名的源素材 URL；反馈仅保留路径、请求或任务标识及脱敏错误摘要。
- **依据实际返回解释**：使用友好模型名；不编造单项生成状态、错误或未返回的媒体属性。模型能力与限制以接口定义和实际响应为准，不套用其他生成接口的别名或默认参数。
- **认证与付费按用户选择处理**：缺失凭证、认证或计费失败时停止生成流程，按认证指引执行。短信在用户选择手机号路径后发送，充值订单在用户选定套餐及支付方式后创建，不主动轮询支付；不将登录令牌、验证码或密钥写入任务 JSON、缓存或源码。归属或权限错误不解释为充值问题。

## 使用示例

### 修改已有视频背景

用户：把这段视频背景换成明亮客厅，保持商品和镜头节奏不变。

核对源视频和编辑要求，选择支持的模型，通过完整流程先上传素材、创建一次任务、等待结果并交付本地视频。

### 使用参考图调整风格

用户：按这些参考图调整视频风格。

核对素材及目标风格，按原顺序上传参考图，生成后展示本地结果与实际费用。

### 继续已有任务或重试下载

用户：继续处理上次没完成的任务。

使用已保存任务编号继续查询；若已有成功查询 JSON，仅恢复下载，不重新生成。
