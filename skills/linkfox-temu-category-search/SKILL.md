# Temu 类目检索与同步

## 适用范围

### 适用

在 Temu 类目库中按中文名、英文名或类目编号查找类目，或在类目库尚未同步时准备类目数据。
用户提到 Temu 类目、Temu category id、Temu 类目树、Temu 后台类目、Temu 品类或同步后查询类目时，使用本技能，无需明确提及工具名。

**场景速查**

| 用户表达 | 查询场景 |
|---|---|
| 找厨房相关的 Temu 类目编号 | 关键词检索：匹配类目中英文名称和编号。 |
| 这个类目属于哪一级、上级是什么 | 类目核对：查看层级、父类目和是否有子类目。 |
| 类目库还没数据，先同步再查询 | 数据准备：同步类目树，再检索目标类目。 |

## 接口清单

| 接口 | 端点 | 对应脚本 | 说明 |
|---|---|---|---|
| Temu 品类查询（temuCategorySearch） | POST `/ehunt/temu/temuCategorySearch` | `scripts/temu_category_search.py` | 检索已同步到本地库的类目。 |
| Temu 品类同步（syncTemuCategory） | POST `/ehunt/temu/syncTemuCategory` | `scripts/temu_category_search.py --sync` | 拉取分类树写入本地库。 |

## 前置条件

执行检索时，先确定类目关键词，并确认类目库已同步；仅同步类目树时无需关键词。需要准备类目库时按用户任务范围执行同步。详细数据范围和参数要求见 [接口定义](references/api.md)。

## 查询流程

1. 确定用户需要类目定位、层级核对还是同步类目数据。
2. 对尚未同步的类目库，先执行类目同步，按 [接口定义](references/api.md) 确认同步成功；仅要求同步时展示同步结果后结束，需要检索时再继续。同步失败时先解释原因并处理，不将旧数据当作本次同步结果。
3. 读取 [接口定义](references/api.md)，使用用户给定的关键词检索，并按任务范围查看后续页。
4. 根据返回的名称、编号和父子关系核对类目，将匹配结果交给商品或店铺筛选流程使用。

## 执行方式

- **直接调用接口**：接口端点、完整参数、响应和错误码见 `references/api.md`。
- **脚本调用（推荐）**：`python <脚本路径> '<JSON 参数>' [--inline] [--no-cache]`。
- **调用约束**：同一会话、同一参数组合默认只调用一次，脚本提供 24 小时本地缓存。失败或空结果时，先核对同步状态、关键词与错误原因，再按用户任务范围继续，不自动连续换词、翻页或反复同步。

### 输出策略

- 始终保存完整响应，默认目标路径为 `<cwd>/linkfox/<YYYY-MM-DD>/<session>/data/linkfox-temu-category-search-<timestamp>.json`。`<cwd>` 为脚本运行时的工作目录，`<session>` 优先取环境变量 `SESSION_ID`，用于聚合同一任务的数据。运行前确认工作目录和配置的输出根目录可写，禁止写入 `/tmp`；脚本的目录候选顺序见 [运行约定](references/api.md#缓存与输出)。
- 响应体不超过 8 KB：保存后，将完整 JSON 打印到标准输出。
- 响应体超过 8 KB：保存后，标准输出仅展示摘要，包括顶层字段、常见计数（如 `total`）、最大列表字段的长度和前 3 条样本。
- 添加 `--inline` 可强制全量打印到标准输出，同时仍保存文件。

先通过摘要判断数据是否足够。需要具体字段时，优先使用 `jq` 或 `ConvertFrom-Json` 从保存的 JSON 文件按需提取，避免将整份响应载入上下文。

## 执行规则

### 算力消耗预估

本技能的类目检索与同步不消耗算力 （限时）。

**声明**：算力消耗以实际扣除为准；如因需要调整算力消耗标准，恕不另行通知。最终解释权归 LinkFox 官方所有。

### 解决认证和算力问题

出现以下情况时，按 `references/onboarding.md` 的指引处理：

- 未配置接口密钥：`LINKFOX_AGENT_API_KEY` 和 `LINKFOXAGENT_API_KEY` 均为空。
- HTTP 状态码为 `401` 或 `402`。
- 响应提示算力或余额不足、计费不足、配额超限、套餐到期或需要充值。英文错误消息也按其含义判断。

### 约束与建议

- **理解数据来源**：检索的是已同步到本地库的类目资料，不是 Temu 前台商品结果。
- **清晰展示类目**：用表格展示中英文名称、类目编号、父类目编号、层级、删除状态及是否有子类目；仅展示实际返回的数据。
- **衔接后续筛选**：返回的 `id` / `categoryId` 可作为商品查询的 `categoryHome` / `categoryBackend`、店铺查询的 `category` 等类目标识，按具体工具的 schema 选择，不能混淆两个编号。
- **解释返回范围**：展示本次实际返回的类目，不将当前页条数当作所有匹配类目的总数。
- **处理空结果**：先核对同步状态和用户关键词，说明原因，再按用户任务范围继续；不自动反复同步或换词试探。
- **使用已有输出**：优先复用已取得的数据；同步后的数据刷新方式、缓存、CLI 和环境变量说明见 [运行约定](references/api.md#脚本运行约定)。

## 使用示例

### 定位用于筛选的类目

用户：找一下厨房用品对应的 Temu 类目编号。

用户：类目库还没同步，先同步再查厨房类目。
