# Temu 店铺查询

## 适用范围

### 适用

查找和筛选 Temu 市场店铺，对比店铺的销量、销售额和经营指标。
用户希望按名称或编号找店、查看某个国家或类目的店铺、比较全托管与半托管店铺表现时，使用本技能。

**场景速查**

| 用户表达 | 查询场景 |
|----------|----------|
| 找一下这个名称或 ID 对应的 Temu 店铺 | 店铺定位：查看匹配店铺及经营数据。 |
| 看美国站周销量靠前的店铺 | 店铺排行：按站点和销量筛选、排序。 |
| 找这个类目里的半托管店铺 | 竞店发现：结合类目与托管模式筛选。 |
| 看评分高、粉丝多的新店 | 多维筛选：结合评分、粉丝和开店时间。 |
| 对比几家店的月销量和销售额 | 店铺对比：展示同一统计口径的经营指标。 |

## 前置条件

根据用户的筛选目的整理已提供的条件；店铺名称或编号、站点和类目均为可选，不要求排行或竞店发现任务先提供具体店铺。需要站点或类目筛选时，先确认相应编号，不凭名称编造编号。参数与限制见 `references/api.md`。

## 查询流程

1. 将用户的店铺、市场、类目、托管模式和指标要求整理为查询条件，按 `references/api.md` 核对区间、日期、排序及分页约定。
2. 说明按返回店铺数动态计费的预估及继续查询的成本，由用户决定是否继续，再执行查询；相同条件优先复用缓存。
3. 核对响应，展示匹配总量、本页店铺及主要指标。错误或空结果按接口参考解释，后续检索遵守成本约束。

## 执行方式

- **直接调用接口**：接口端点、完整参数、响应和错误码见 `references/api.md`。
- **脚本调用（推荐）**：`python scripts/temu_store_query.py '<JSON 参数>' [--inline]`。
- **成本约束**：本工具按本页返回店铺数量 × 1.8 计费。同一会话、同一参数组合默认只调用一次，脚本提供 24 小时本地缓存。失败或空结果时，不得自动更换关键词、翻页或修改筛选条件连续试探；需要继续检索时，先向用户说明额外消耗。

### 输出策略

- 始终保存完整响应，目标路径为 `<cwd>/linkfox/<YYYY-MM-DD>/<session>/data/linkfox-temu-store-query-<timestamp>.json`。`<cwd>` 为脚本运行时的工作目录，`<session>` 优先取环境变量 `SESSION_ID`，用于聚合同一任务的数据。禁止写入 `/tmp`，当前目录不可写时应报错。
- 响应体不超过 8 KB：保存后，将完整 JSON 打印到标准输出。
- 响应体超过 8 KB：保存后，标准输出仅展示摘要，包括顶层字段、常见计数（如 `total`、`costToken`）、最大列表字段的长度和前 3 条样本。
- 添加 `--inline` 可强制全量打印到标准输出，同时仍保存文件。

先通过摘要判断数据是否足够。需要具体字段时，优先使用 `jq` 或 `ConvertFrom-Json` 从保存的 JSON 文件按需提取，避免将整份响应载入上下文。

## 执行规则

### 算力消耗预估

按动态规则计费：消耗算力 = 本页返回店铺数量 × 1.8。翻到下一页是再次请求，按下一页返回条数重新计费。单次可能消耗大量算力，必须提醒用户，由用户决定是否继续。

**声明**：算力消耗以实际扣除为准；如因需要调整算力消耗标准，恕不另行通知。最终解释权归 LinkFox 官方所有。

用户会因算力消耗而支付费用。需要高频调用或用户对消耗量预期不足时，提醒用户，并由用户决定是否继续。

### 解决认证和算力问题

出现以下情况时，按 `references/onboarding.md` 的指引处理：

- 未配置接口密钥：`LINKFOX_AGENT_API_KEY` 和 `LINKFOXAGENT_API_KEY` 均为空。
- 响应状态码为 `401` 或 `402`。
- 响应提示算力或余额不足、计费不足、配额超限、套餐到期或需要充值。英文错误消息也按其含义判断。

### 约束与建议

- **区分计数口径**：`total` 是本页返回条数，`storeNum` 是符合条件的店铺总数；不得将匹配总量当作本页计费数量。
- **清晰展示数据**：先说明查询范围与排序，再用表格列出店铺 ID、名称、站点、托管模式、总/周/月销量、销售额、评分及用户关心的评论、粉丝、商品数、类目和开店时间。缺失指标按缺失展示，不补造数值。
- **保留统计口径**：销售额按美元（USD）展示；比较店铺时保持销量与销售额的周期一致。不要把周销量、月销量和总销量混为同一指标。
- **说明数据来源**：这是市场数据查询，不代表用户自己已授权店铺的后台数据。MCP 展示名为“Temu 店铺查询”，实际工具名以当前环境元数据为准。
- **处理空结果和错误**：无匹配数据与请求错误分开解释，保留已取得的数据。响应判断和部署路径问题见 `references/api.md`。
