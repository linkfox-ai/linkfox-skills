# 亚马逊 Alexa 购物助手

## 适用范围

### 适用

用户希望在亚马逊前台用自然语言提出购物需求，获得推荐并继续追问时，使用本技能。

**场景速查**

| 用户表达 | 查询场景 |
|----------|----------|
| 用 Alexa 帮我推荐跑步耳机 | 自然语言导购问答。 |
| 在亚马逊找适合某用途、某预算的商品 | 结合用途、预算和功能要求推荐。 |
| 顺便再追问一下，接着问 | 总结已有回答，再发起追问。 |
| 基于这个页面或分类推荐商品 | 结合具体页面上下文提问。 |
| 对比 Alexa 给的前两个推荐 | 根据已有推荐开展比较。 |
| Alexa 还能继续问什么 | 展示返回的追问建议。 |

### 边界

完整 SERP、排名和广告标记使用前台搜索技能；历史搜索词及搜索量趋势使用 ABA 数据技能；已知 ASIN 的完整详情、A+ 和五点描述使用商品详情技能；逐条评论情感分析使用评论技能；图片找同款使用以图搜图技能。对扁平商品表做聚合统计也不属于本技能范围。

## 前置条件

先确定用户的购物问题；将用户已提供的站点、使用场景、预算和硬性功能要求纳入问题，不要求每次补齐这些条件。已有回答或具体页面时保留相关上下文。参数与使用限制见 `references/api.md`。

## 查询流程

1. 将站点、用途、预算和硬性要求放在问题开头，让 Alexa 优先理解用户意图。
2. 用户追问时，先总结上一轮回答的关键结论、推荐商品和 ASIN，再拼接新问题；上下文传递方式和长度限制见 `references/api.md`，不要假设 Alexa 记得上次回答。
3. 用户围绕某个具体页面提问时，结合页面上下文；常规导购直接提问。页面与输出格式的选择要求见接口定义。
4. 仅展示回答时选择可读报告；后续需要提取 ASIN、价格或追问内容时选择结构化结果。
5. 调用后先判断响应状态，再展示导购回答、推荐商品组和可继续追问的问题。出现空结果或错误时，按接口定义解释原因；继续检索须遵守成本约束。

## 执行方式

- **直接调用接口**：接口端点、完整参数、响应和错误码见 `references/api.md`。
- **脚本调用（推荐）**：`python scripts/amazon_alexa_search.py '<JSON 参数>' [--inline]`。
- **成本约束**：本工具按对话轮次计费，具体规则见“算力消耗预估”。同一会话、同一参数组合默认只调用一次，脚本提供 24 小时本地缓存。失败或空结果时，不得自动更换关键词、翻页或修改邮编连续试探；需要继续检索时，先向用户说明额外消耗。

### 输出策略

- 始终保存完整响应，目标路径为 `<cwd>/linkfox/<YYYY-MM-DD>/<session>/data/linkfox-amazon-alexa-search-<timestamp>.json`。`<cwd>` 为脚本运行时的工作目录，`<session>` 优先取环境变量 `SESSION_ID`，用于聚合同一任务的数据。禁止写入 `/tmp`，当前目录不可写时应报错。
- 响应体不超过 8 KB：保存后，将完整 JSON 打印到标准输出。
- 响应体超过 8 KB：保存后，标准输出仅展示摘要，包括顶层字段、常见计数（如 `total`、`costToken`）、最大列表字段的长度和前 3 条样本。
- 添加 `--inline` 可强制全量打印到标准输出，同时仍保存文件。

先通过摘要判断数据是否足够。需要具体字段时，优先使用 `jq` 或 `ConvertFrom-Json` 从保存的 JSON 文件按需提取，避免将整份响应载入上下文。

## 执行规则

### 算力消耗预估

按对话轮次动态计费，预估 13 算力/轮（￥0.13/轮）。

> **重要**：本技能的服务按倍数动态计算，可能一次性消耗大量算力，必须提醒用户，由用户决定是否继续。

**声明**：算力消耗以实际扣除为准；如因需要调整算力消耗标准，恕不另行通知。最终解释权归 LinkFox 官方所有。

用户会因算力消耗而支付费用。需要高频调用或用户对消耗量预期不足时，提醒用户，并由用户决定是否继续。

### 解决认证和算力问题

出现以下情况时，按 `references/onboarding.md` 的指引处理：

- 未配置接口密钥：`LINKFOX_AGENT_API_KEY` 和 `LINKFOXAGENT_API_KEY` 均为空。
- 响应状态码为 `401` 或 `402`。
- 响应提示算力或余额不足、计费不足、配额超限、套餐到期或需要充值。英文错误消息也按其含义判断。

### 约束与建议

- **理解会话含义**：Alexa 给出的是对话式回答和少量精选推荐。每次请求是新会话，追问由本技能总结上下文后重新提问；这不是完整搜索结果提取或扁平表聚合分析工具。
- **保留报告结构**：可读报告直接按返回的问题标题、回答、商品组和追问结构呈现。
- **展示商品分组**：保留推荐分组，展示商品标题、ASIN、价格、评分、评价数量和商品链接；存在截图或简述时按需展示，不补造缺失信息。
- **展示追问建议**：列出 Alexa 返回的可继续追问问题。用户选择后，按查询流程总结当前回答，再发起新的追问。
- **说明结果时效**：回答会随时间、流量及上下文变化，同样问题可能得到不同推荐；用户关心时间时，注明回答反映调用时的情况，缓存命中时说明复用了保存结果。
- **解释空结果与业务错误**：按 `references/api.md` 判断并展示可用错误消息；可建议简化问题或结合具体页面重问，遵守成本约束，不自动连续试探。

## 使用示例

### 单轮购物推荐

```json
{"prompts": ["best wireless earbuds for running on Amazon US under $100"]}
```

### 总结上下文后追问

先询问电热水壶推荐：

```json
{"prompts": ["best electric kettle on Amazon US"]}
```

若上一轮实际返回以下商品，可总结后追问（商品和价格仅为示例，实际使用响应中的值）：

```json
{"prompts": ["上轮推荐：Cosori 电热水壶（B07T1KY5TZ，$35.99，4.7星）和 Mueller Ultra 电热水壶（B09KC7D3HR，$29.97，4.5星）。请比较二者的噪声和烧水时间。"]}
```

### 结合具体页面提问

```json
{"prompts": ["这个页面有哪些热门推荐？"], "url": "https://www.amazon.com/s?k=electric+kettle"}
```

### 获取结构化推荐

```json
{"prompts": ["best gift ideas for a 10-year-old who likes science"], "format": "json"}
```
