# Amazon 店铺授权快速开始

## 准备

确认 LinkFox 身份凭据已配置，缺失按 [认证引导](onboarding.md) 处理。服务端需具备可用紫鸟代理、数据库与正确 gateway.url，回调地址需加白名单。客户端认证使用 API Key，不额外添加 Bearer 前缀。

## 新增连接

先按 [授权与店铺管理流程](../SKILL.md#授权与店铺管理流程) 选择手动或自动方式。手动模式确认店铺名与目标站点后生成链接，紧接链接逐字展示入口的安全警告；自动模式完整执行 [紫鸟 CLI 自动授权](automatic-authorization.md)。参数与完整示例统一见 [接口说明](api.md)，CLI 见 [脚本指南](../scripts/README.md)。

## 核验与后续业务

1. 用户完成本次回调后查询已授权店铺，核对卖家和区域。历史记录不单独证明本次 OAuth 成功。
2. 可选查询授权状态；ACTIVE 可继续，EXPIRED 或令牌失效时刷新，失败则解释原因并按规则处理。
3. 将选定 sellerId + region 交给下游报告、订单等业务技能；不取 raw token。后端负责令牌存储，developerProxy 识别到上游令牌过期或失效响应时会刷新并重试一次；客户端不增加令牌缓存或响应缓存。
4. 多店铺或多区域分别授权并明确目标；批量授权的并发和收尾使用自动授权文档，批量业务由下游控制并发。

## 解绑与重新授权

只在用户要求时解绑，明确区域与成员身份影响，按 [接口定义](api.md#接口本地解绑cancelauthorization) 解读结果。共享授权和其他成员连接保留，不能宣称 LinkFox 全局停止使用；如要 Amazon 官方撤权，由卖家到授权管理页操作。未完成回调仍可能恢复绑定，不自动重新授权。

## 故障处理

生成链接失败检查网络、紫鸟服务与回调白名单；本次回调未保存时检查 state 的用户上下文与服务端日志，不打印完整回调凭据。1004 时先核对已授权列表、卖家和区域，缺失/失效的 refresh_token 需重新授权。下游令牌失效时刷新后只按对应业务技能的规则谨慎重试一次，仍失败则停止；店铺保护冷却优先于一般重试建议。

更多后台模型与排查见 [服务端背景](authorization-flow.md)，冷却与停止范围见 [店铺保护](spapi-protection.md)。
